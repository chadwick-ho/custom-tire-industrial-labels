Decimal Separators in Variable Label Data Need a Numeric Import Proof

Published November 20, 2026

An equipment buyer sends a data file prepared under one regional convention to a print workflow using another. A decimal comma or grouping mark survives as text, yet the importer may assign it a different numeric meaning. Before ordering the populated labels, approve the numeric value that the actual print path receives.

Separate parsing from the final display rule

Have the data owner identify fields that are numbers and fields that are identifiers. An ID resembling a number should not be converted merely because a spreadsheet can calculate with it. For numeric fields, specify the source decimal and grouping conventions, any allowed sign, and the expected units. Record the importer and the locale used for each relevant conversion rather than assuming the workstation's regional setting is decisive.

Prepare harmless witness rows with independent expected values. In an illustrative source using a decimal comma, the text 12,50 is intended to represent twelve and a half. Keep that intended value beside the raw field, then capture the import result. Do not guess how an unqualified program will interpret the same characters. Include a grouping example and any boundary or invalid value that the actual order permits.

Only after the parsed values agree should the owner approve rounding, decimal places and the printed expression. Quoting a comma correctly in CSV solves the field boundary; it does not choose the numeric interpretation inside that field. Likewise, a neat proof showing two decimal places can conceal a wrong underlying value. Compare the decoded value too if the numeric data is encoded.

Microsoft’s Power Query locale guidance describes regional settings at operating-system, query and conversion-step levels. It is an example of why an explicit conversion rule matters; another label importer needs its own documentation.

What to include in the approval record

Review pointEvidence to keep
Field contractNumeric versus identifier type, source convention and units.
WitnessRaw source text and independently approved numeric meaning.
ImportActual parsed value and conversion configuration reference.
OutputApproved display and any encoded numeric representation.

Before approving the order

Hold records with an unexplained conversion or silently removed punctuation. A supplier-ready column of approved text can be simpler when no numeric calculation is needed, provided its exact reproduction is checked. Do not change equipment ratings or order quantities merely to fit an import default.

For custom variable data labels, send harmless source rows, intended numeric values, field types, importer details and required printed quantities.
