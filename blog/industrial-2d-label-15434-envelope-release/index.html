Industrial 2D Labels: Approve the Message Envelope, Not Just the Printed Fields

Published November 27, 2026

A supplier returns a neat 2D label proof. The product, quantity and package fields look correct, but the receiving application rejects the message. If the customer specifies a message envelope, the buyer needs evidence of that framing as well as the visible fields. A readable code image alone does not settle the handoff.

Obtain the receiver specification before building the symbol

Ask the receiving-system owner to identify the required carrier, message syntax, format, data identifiers, permitted content and applicable specification revision. Keep those as separate entries. Choosing Data Matrix or PDF417 describes a carrier; it does not by itself define the message structure the receiver expects.

ISO's public listing for ISO/IEC 15434:2025 describes message transfer structure and syntax for high-capacity ADC media. It lists the 2019 edition as withdrawn. The public scope is not the full procedure, and a customer's controlled implementation may reference a particular edition. Resolve the applicable requirement with its owner rather than silently changing an existing interface.

Build an approval record with the required header and trailer, field order, actual control characters and the software's input convention. A specification may display readable names such as GS, RS and EOT for nonprinting controls. Typing those letters is not automatically the same operation as supplying the controls. Conversely, the exact input notation depends on the generating software; a token copied from a different tool can become ordinary payload text.

Witness the framing through the real receiving path

Have the encoder owner generate a representative, clearly identified non-production witness using the agreed convention. Where the receiving owner has an approved diagnostic route, retain the recovered controls in an unambiguous escaped or hexadecimal representation, alongside the intended field map and actual parsed result. An ordinary text editor can hide controls, and a keyboard output path may transform them.

Compare source fields, envelope boundaries and receiving result separately. If an end marker is absent or a control has become visible letters, preserve that observation before changing artwork. Also distinguish controls encoded in the message from characters the reader adds to its output. A successful print-quality check does not decide which layer changed the message.

Volkswagen Group's public Global Transport Label FAQ, dated October 14, 2025, requires ISO/IEC 15434 syntax controls for its described 2D label application. That is an application-specific example, not a requirement for all industrial labels or evidence of CYJ approval by that customer.

What to include in the approval record

Review pointEvidence to keep
RequirementReceiver-owned carrier, message format, edition and implementation reference.
GenerationApproved fields, envelope/control map, software input convention and output revision.
WitnessIdentified printed sample, diagnostic controls, device/output path and parsed application result.
ReleaseData-owner and receiving-owner agreement, with unresolved differences stated.

Before approving the order

Hold production if the receiver cannot establish the required envelope or the witness parses differently. An internal label carrying only an approved ordinary identifier may not need this structure. Keep that simpler contract if the system owner confirms it; do not add a standard envelope merely because a 2D symbol can hold more data.
