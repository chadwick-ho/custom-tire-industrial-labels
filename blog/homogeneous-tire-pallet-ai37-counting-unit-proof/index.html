A Homogeneous Tire Pallet Count Needs a Defined Counting Unit

Published November 22, 2026

A packing record says six tires, while the outer label says three units. Both numbers could describe the same load if it contains three two-tire cases. For a homogeneous GS1 logistics-label workflow using AI 02 for contained trade items, approve what is being counted before choosing the AI 37 value. A larger count is not automatically the more accurate one.

Attach the quantity to the contained item

Ask the identifier owner to name the contained trade item represented by the approved GTIN. Then reconcile its counted units to the actual packed load. In the fictional three-case example, a case reference and a tire reference would need different matching counts. Do not infer which level applies from the visible tire size or a warehouse column named quantity.

GS1 Denmark’s application-identifier guidance states that a logistics unit using AI 02 must also include AI 37 and AI 00. Use the applicable partner implementation and current GS1 requirements to approve the complete combination. AI 37 is not a general place to paste any number found on the order. Do not substitute AI 30 simply because the number of tires changes between shipments; that field belongs to variable-measure rules and needs its own qualified review.

Make a proposed acceptance record with the contained GTIN, item description and packaging level, the count of those items, pallet identity and packing-record revision. Retain a physical count witness or the buyer-approved packing confirmation method. Keep any readable total-tire summary explicitly separate if it counts at another level.

When the load contains different trade items, stop applying a single-item count model and use the agreed mixed-load approach. When the predefined case contents change, obtain the separate case-GTIN disposition. Neither a label designer nor a barcode generator can settle those product-data decisions from arithmetic alone.

GS1 Denmark’s guidance on mandatory AI combinations supports the data relationship. The fictional packing example is an editorial aid, not an assigned GTIN or a complete encoding specification.

What to include in the approval record

Review pointEvidence to keep
ObjectApproved contained GTIN, description and packaging level.
CountActual quantity at that same level and confirmation method.
UnitApproved logistics-unit identifier and complete partner-required field set.
ComparisonDecoded fields and readable summary checked against the same released packing record.

Before approving the order

Hold if the count has no defined unit or if one item is used to represent a heterogeneous load. A shipment using an internal non-GS1 label can retain its approved internal counting convention; do not add GS1 field names merely to decorate the artwork.

For tire barcode labels, send the contained-item record, physical packing example, partner label requirement, dimensions and label quantities for the pallet-label proof.
