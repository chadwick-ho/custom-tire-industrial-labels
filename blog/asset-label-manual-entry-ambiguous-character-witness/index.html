Asset Label IDs: Check Whether People Can Distinguish O From 0

Published November 26, 2026

A maintenance workflow sometimes requires staff to type an asset ID from the sticker. The barcode decodes correctly, yet the readable line contains characters that are difficult to distinguish at its installed size. Review that human-reading task separately before approving the layout.

Keep character identity separate from its visible glyph

Ask the data owner which characters can occur in the actual ID scheme and whether manual entry is part of the approved workflow. Keep the full identifier unchanged. A letter O and a digit zero may identify different records even when a chosen typeface makes them look similar.

Prepare harmless witness IDs using the relevant confusing characters, plus representative lengths. Have the print owner render them through the intended template, font and device at finished size. Review the applied position, lighting and reading distance expected by the process owner, rather than judging an enlarged screen preview.

For a transcription witness, let an intended reader copy the visible test string without first seeing the answer key. Compare the copied value with the approved source afterward and record the exact differences. This proposed check reveals an observed ambiguity; a small witness set does not establish a universal error rate or guarantee every operator’s performance.

A supported alternate glyph or a different suitable font may improve distinction. Microsoft’s OpenType specification describes a slashed-zero feature intended to distinguish zero from capital O, including in labels. Confirm both font support and the real output path; selecting a feature in one design application does not prove that a device font or substituted renderer preserves it.

Changing the glyph is not permission to replace the digit with a slash, the letter O or another Unicode character. Recheck the exact source value, encoded content and receiving lookup after a typography change. Retain barcode quality and operational scanning as separate checks from human transcription.

Microsoft’s OpenType feature reference, zero feature describes an alternate visual form of the same zero character. It does not certify a typeface, printer route or human-reading outcome for this order.

What to include in the approval record

Review pointEvidence to keep
Data contractPermitted alphabet, complete approved ID and manual-entry requirement.
TypographyFont and supported alternate-glyph setting through the actual renderer.
Reading witnessFinished-size installed context, test key, copied value and observed discrepancies.
Identity checkSource string and any encoded/lookup value remain unchanged.

Before approving the order

Hold the readable-field approval if a required ID cannot be distinguished in the intended use position. Compare supported typography, available space or an owner-approved label layout before proposing a new identifier scheme.

If the owner chooses to exclude ambiguous characters from newly allocated IDs, treat that as a separate data-policy decision. Do not silently rewrite identifiers already assigned to equipment.
