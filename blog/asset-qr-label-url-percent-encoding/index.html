Asset QR Label URLs: Preserve Reserved Characters Through the Print File

Published November 11, 2026

An asset record owner supplies a URL containing a percent escape. Someone decodes it while tidying the spreadsheet, and the new QR still opens a web page. The page belongs to a different route. A successful browser launch has not established that the approved link survived.

Have the record owner release the complete URL

Keep the URL as a controlled string, including its scheme, path, query and any fragment. The site or application owner should generate and approve it. The label supplier should not assemble addresses from screenshots, remove punctuation or decode escapes to make a spreadsheet easier to read.

RFC 3986, sections 2.1, 2.2 and 2.4, explains percent encoding and reserved delimiters. Replacing a reserved character with its encoded form, or reversing that operation, can change a URI's interpretation. That is a reason to preserve the owner's released string, not a rule to encode every punctuation mark in a URL.

Test a route that exposes the difference

In an illustrative path comparison, /asset/A%2FB contains an encoded slash within the submitted segment, while /asset/A/B exposes an additional path separator. The application owner must determine what either route means on its system. Neither example is a live asset address or a proposed production URL.

Select actual approved witness records containing the punctuation used by the order. Include a normal record as a control. If a URL is embedded in CSV, a template or another file format, also confirm that its container escaping is interpreted correctly. Do not confuse the container's representation with the string the QR is supposed to encode.

Do not let the browser conceal a data change

Compare the decoded payload with the released source before relying on the page display. Browser address bars and redirects can present addresses differently. A scanner application may also process the capture before opening it. Preserve the original decoded evidence where the owner's approved tools permit it.

If a string changes, stop release for the affected records and find the first changed handoff. If the exact approved URL survives but resolves incorrectly, involve the application owner rather than changing the label artwork by guesswork. A corrected route still requires a finished-size scan review where print quality matters.

This check applies to QR codes carrying URLs. A code containing only an internal asset ID needs its own data contract. The link-ownership guide addresses who maintains the destination over time.

For asset QR label projects, send an approved non-sensitive witness URL list, expected records, template/data format, label dimensions and quantity. Keep credentials and private records outside the printed payload.
