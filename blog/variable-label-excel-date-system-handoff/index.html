Variable Label Dates From Excel: Check the Workbook Date System Before Handoff

Published November 25, 2026

An equipment-label buyer approves service-record dates in an Excel workbook. Another workbook or print-data step receives the underlying numbers, and the resulting labels show different calendar dates. Check the workbook date system before treating the error as a text-formatting problem.

Preserve the calendar value across the actual handoff

Excel supports the 1900 and 1904 date systems. Microsoft documents a 1,462-day difference between the serial numbers representing the same date in the two systems. A bare number without its interpretation is therefore an incomplete date handoff. This issue is separate from choosing day-month order for a date already interpreted correctly.

Ask the data owner whether the released field is a numeric Excel date, date text or another defined type. Identify the source workbook’s date system and any intermediate workbook, export or connector. Do not infer a workbook’s setting from the computer brand or the file’s appearance.

Prepare a small witness set with owner-approved calendar dates, record keys and an explicit readable reference. Pass it through the same copy, export and import route intended for production. Compare the received values and actual label output with the approved calendar reference. Include a recent date, a year boundary and a missing value under the owner’s exception rule.

If a mismatch appears, preserve the original workbook and identify the step that changes the interpretation. Have the source and print-data owners agree a controlled correction. Do not add or subtract 1,462 from an entire column merely because one label is wrong: the handoff may already convert values, or the column may contain mixed representations.

One agreed date-text export can simplify a handoff when the recipient accepts it, provided the parser and resulting date are also checked. A CSV field does not carry the source workbook’s date-system setting as workbook metadata. Record exactly what representation the receiving route expects rather than relying on a screenshot of formatted cells.

Microsoft’s explanation of Excel date systems documents the two systems and their serial-number difference. Its description does not establish how a particular label-software connector imports dates; witness that actual route.

What to include in the approval record

Review pointEvidence to keep
SourceWorkbook revision, date system, field type and owner-approved calendar reference.
RouteAny intermediate workbook, export representation and recipient parser.
WitnessRecord keys, expected calendar dates, received values and actual label output.
CorrectionOwner-approved transformation, retained original and evidence that conversion occurs only as intended.

Before approving the order

Hold the affected date-bearing variants when the calendar values change or the interpretation is unknown. Do not relabel a receipt date as a manufacture or expiry date to make an output look plausible. Field meaning and permission to print the date remain separate approvals.

When the released data is already unambiguous date text and no workbook-serial interpretation occurs, use a simpler parser-and-output witness. This check is useful where numeric workbook dates actually cross the handoff.
