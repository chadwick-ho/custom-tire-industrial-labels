GS1 Net-Weight Labels: Approve the Decimal Indicator With the Six Digits

Published November 25, 2026

A receiving program requires a GS1 net-weight field for a variable-measure trade item. The source file contains an approved kilogram value, but the returned proof uses a six-digit magnitude. Approve the Application Identifier and the magnitude together before the data reaches the barcode artwork.

Keep the implied decimal with the quantity

Start only after the data-standard owner has confirmed that this GS1 attribute is appropriate for the item and receiving application. AI 310n concerns net weight in kilograms for a variable-measure trade item. It is not a general heading to attach to every drum weight or a replacement for the applicable identifier associations.

In this family, the fourth AI digit identifies decimal places. GS1’s current AI data describes 3103 as a six-digit field interpreted as nnn.nnn kilograms. For a fictional field-only example, AI 3103 with magnitude 012345 expresses 12.345 kg. With AI 3102, those same six magnitude digits express 123.45 kg. The digits have not changed, but the represented amount has.

These examples are not complete, allocated or verified GS1 symbols. They supply no product identifier. Have the standards owner supply the complete permitted field specification, required associations and carrier. Do not print an invented GTIN merely to make a demonstration look complete.

For each representative record, retain the approved quantity and units, intended AI, generated magnitude and expected parsed value. Include values with trailing fractional zeros and values near the allowed field range when relevant to the real specification. Have the owner define precision, rounding and out-of-range behavior before conversion. Do not truncate digits until the field fits.

Request a real generated proof through the intended encoder and receiving parser. Reconcile the parsed value and readable quantity against the same released source record. The supplier’s input interface may expect a decimal value, six digits or another documented convention; agree that convention rather than assuming the visible decimal point should be encoded literally.

GS1’s AI 3103 reference and linked current dataset specify its six-digit magnitude and implied decimal interpretation. The data owner must apply the current complete GS1 and receiving requirements to the actual item.

What to include in the approval record

Review pointEvidence to keep
ApplicabilityOwner-approved attribute, carrier, required associations and receiving specification.
SourceApproved net quantity in kilograms, precision and source-record revision.
TransformationSelected decimal indicator, generated magnitude and exception rules.
WitnessReadable amount and actual parsed value compared with the released source.

Before approving the order

Hold output if the interpreted amount differs or the source lacks an approved precision rule. Keep the uncertainty as a named exception; neither a scan beep nor six well-printed digits approves the quantity.

For a plain internal readable-weight label with no GS1 attribute requirement, reproduce the owner-approved value and unit without adding this encoding structure. The printer does not determine the chemical contents, weighing result or legally required declaration.
